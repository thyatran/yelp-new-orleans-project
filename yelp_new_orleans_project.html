1. Introduction & Research Question

1.1 Project Overview

This project uses the Yelp Open Dataset to analyze restaurants in New Orleans, Louisiana. It combines restaurant information, customer reviews, and geographic data to examine how restaurant ratings and locations vary across the city.

The analysis includes data cleaning, category selection, relational joins, geographic comparisons, and reviewer-adjusted ratings. The goal is to identify highly rated restaurants within a selected category group and determine which geographic areas offer the strongest options.

1.2 Research Question

Which Cajun/Creole, Seafood, and Southern restaurants in New Orleans rank highest after adjusting for reviewer rating habits, and which census tracts offer the strongest restaurant options?

1.3 Project Objectives

  • Select and analyze at least three related restaurant categories.
  • Compare restaurant ratings and review activity.
  • Evaluate different geographic systems for analyzing restaurant locations.
  • Compare ratings from all reviewers with reviewer-adjusted scores.
  • Identify the top 10 restaurants and map their locations.
  • Discuss findings, limitations, and data management decisions.

2. Data Collection & Preparation (Homework 5)

2.1 Data Source

The data comes from the Yelp Open Dataset, which contains information about businesses and customer reviews.

Two datasets were used:

  • Business dataset: Contains restaurant names, addresses, locations, ratings, review counts, and categories.
  • Review dataset: Contains individual customer ratings, review text, reviewer IDs, and review dates.

The datasets are connected through business_id, allowing each restaurant to be matched with its customer reviews.

Source: Yelp Open Dataset

2.2 Data Importing & Cleaning

The original Yelp data was provided as large JSON files. The business dataset was imported using jsonlite::stream_in(), while the review dataset was processed in smaller chunks to reduce memory usage.

Only the columns needed for the analysis were retained.

6.2 Geographic Summary Statistics

Code 
compare_geography <- function(boundaries, id_column, system_name) {

  assigned <- st_join(
    restaurant_points,
    boundaries |> select(all_of(id_column)),
    left = TRUE
  ) |>
    st_drop_geometry() |>
    mutate(area_id = as.character(.data[[id_column]]))

  multiple_matches <- assigned |>
    filter(!is.na(area_id)) |>
    count(business_id) |>
    filter(n > 1) |>
    nrow()

  matched <- assigned |>
    filter(!is.na(area_id)) |>
    group_by(business_id) |>
    filter(n() == 1) |>
    ungroup()

  area_summary <- matched |>
    group_by(area_id) |>
    summarise(
      restaurant_count = n(),
      average_rating = mean(stars, na.rm = TRUE),
      .groups = "drop"
    )

  all_areas <- boundaries |>
    st_drop_geometry() |>
    transmute(area_id = as.character(.data[[id_column]])) |>
    distinct() |>
    left_join(area_summary, by = "area_id") |>
    mutate(
      restaurant_count = replace_na(restaurant_count, 0L)
    )

  tibble(
    geographic_system = system_name,
    number_of_areas = nrow(all_areas),
    restaurants_assigned = n_distinct(matched$business_id),
    unmatched_restaurants =
      nrow(restaurants) - n_distinct(matched$business_id),
    multiple_area_matches = multiple_matches,
    smallest_area_count = min(all_areas$restaurant_count),
    largest_area_count = max(all_areas$restaurant_count),
    average_restaurants_per_area =
      mean(all_areas$restaurant_count),
    median_restaurants_per_area =
      median(all_areas$restaurant_count),
    areas_under_5 = sum(all_areas$restaurant_count < 5),
    average_business_rating =
      mean(matched$stars, na.rm = TRUE)
  )
}

This project analyzed Yelp restaurant data in New Orleans, focusing on Cajun/Creole, Seafood, and Southern restaurants. A total of 648 restaurants were selected, with 632 located inside the official city boundary and 16 outside.

9.2 Limitations

Several limitations should be considered when interpreting the results:

  • Geographic boundaries: Yelp’s New Orleans city labels do not always match official Census boundaries, resulting in some restaurants appearing outside city limits.
  • Review representation: Yelp reviewers may not represent all restaurant customers, and some restaurants have significantly more reviews than others.
  • Small sample sizes: Some restaurants received relatively few reviews from active reviewers, making their normalized scores less reliable.
  • Reviewer normalization: Adjusting ratings based on individual reviewer averages helps account for rating differences but does not eliminate all forms of bias.
  • Dataset coverage: The analysis reflects restaurants and reviews available in the Yelp Open Dataset rather than a complete or current inventory of New Orleans restaurants.
  • Geographic ranking: Census tracts were ranked using the unweighted average of eligible restaurants’ normalized scores. Tracts with fewer restaurants may have less stable rankings, and restaurants with different review counts contributed equally to the tract average.

9.3 Final Conclusion

Overall, this analysis identified the highest-ranked Cajun/Creole, Seafood, and Southern restaurants in New Orleans after adjusting for differences in reviewers’ rating habits. 3 Southern Girls ranked highest using reviewer-normalized scores, while census tract 22071003702 had the highest average normalized restaurant score among eligible geographic areas.

The findings demonstrate how reviewer behavior and geographic boundaries can influence restaurant comparisons. Although normalization provides an alternative perspective to traditional ratings, the results should be interpreted alongside review counts, sample sizes, and geographic limitations rather than treated as definitive measures of restaurant quality.

10.1 Handling Large Yelp Datasets

The Yelp Open Dataset contains large JSON files that require careful data management. The original business and review datasets were obtained from the Yelp Open Dataset and stored locally in data/raw/. After downloading the Yelp Open Dataset, the archive was extracted locally to access the business and review JSON files used for data preparation. These files were not uploaded to GitHub because of their size.

The business dataset was imported using jsonlite::stream_in(), while the larger review dataset was processed in smaller chunks to reduce memory usage. The data was then filtered to New Orleans restaurants and their associated reviews, reducing the amount of data needed for the remaining analysis.

After cleaning, the datasets contained 2,259 restaurants and 476,421 reviews. These were saved as compressed RDS files to avoid repeatedly importing and processing the original JSON files.

The combined review dataset exceeded GitHub’s 100 MB file size limit, so it was divided into two smaller files: reviews_part1.rds and reviews_part2.rds. These files were combined using bind_rows() during the analysis.

This approach reduced repeated processing, made the project easier to manage, and allowed the cleaned data and analysis code to be maintained separately from the original large JSON files.

compare_geography <- function(boundaries, id_column, system_name) {

  assigned <- st_join(
    restaurant_points,
    boundaries |> select(all_of(id_column)),
    left = TRUE
  ) |>
    st_drop_geometry() |>
    mutate(area_id = as.character(.data[[id_column]]))

  multiple_matches <- assigned |>
    filter(!is.na(area_id)) |>
    count(business_id) |>
    filter(n > 1) |>
    nrow()

  matched <- assigned |>
    filter(!is.na(area_id)) |>
    group_by(business_id) |>
    filter(n() == 1) |>
    ungroup()

  area_summary <- matched |>
    group_by(area_id) |>
    summarise(
      restaurant_count = n(),
      average_rating = mean(stars, na.rm = TRUE),
      .groups = "drop"
    )

  all_areas <- boundaries |>
    st_drop_geometry() |>
    transmute(area_id = as.character(.data[[id_column]])) |>
    distinct() |>
    left_join(area_summary, by = "area_id") |>
    mutate(
      restaurant_count = replace_na(restaurant_count, 0L)
    )

  tibble(
    geographic_system = system_name,
    number_of_areas = nrow(all_areas),
    restaurants_assigned = n_distinct(matched$business_id),
    unmatched_restaurants =
      nrow(restaurants) - n_distinct(matched$business_id),
    multiple_area_matches = multiple_matches,
    smallest_area_count = min(all_areas$restaurant_count),
    largest_area_count = max(all_areas$restaurant_count),
    average_restaurants_per_area =
      mean(all_areas$restaurant_count),
    median_restaurants_per_area =
      median(all_areas$restaurant_count),
    areas_under_5 = sum(all_areas$restaurant_count < 5),
    average_business_rating =
      mean(matched$stars, na.rm = TRUE)
  )
}

## 9. Conclusions & Limitations

### 9.1 Key Findings

This project analyzed Yelp restaurant data in New Orleans, focusing on Cajun/Creole, Seafood, and Southern restaurants. A total of 648 restaurants were selected, with 632 located inside the official city boundary and 16 outside.

The geographic comparison showed that Census tracts provide a useful balance between geographic detail and restaurant coverage. Using average reviewer-normalized scores, census tract **22071003702** ranked highest among eligible tracts, with four restaurants, 147 active-reviewer ratings, and an average normalized score of 0.341.

Reviewer-normalized ratings also produced different restaurant rankings compared with traditional average review ratings. **3 Southern Girls** ranked first with a normalized score of 1.241, followed by **Cafe Porche and snowbar** (0.759) and **La Vie En Rose Cafe** (0.741). **Pelican Bay** moved from 99th to 4th place after normalization within the eligible comparison group.

### 9.2 Limitations

Several limitations should be considered when interpreting the results:

- **Geographic boundaries:** Yelp's New Orleans city labels do not always match official Census boundaries, resulting in some restaurants appearing outside city limits.
- **Review representation:** Yelp reviewers may not represent all restaurant customers, and some restaurants have significantly more reviews than others.
- **Small sample sizes:** Some restaurants received relatively few reviews from active reviewers, making their normalized scores less reliable.
- **Reviewer normalization:** Adjusting ratings based on individual reviewer averages helps account for rating differences but does not eliminate all forms of bias.
- **Dataset coverage:** The analysis reflects restaurants and reviews available in the Yelp Open Dataset rather than a complete or current inventory of New Orleans restaurants.
- **Geographic ranking:** Census tracts were ranked using the unweighted average of eligible restaurants' normalized scores. Tracts with fewer restaurants may have less stable rankings, and restaurants with different review counts contributed equally to the tract average.

### 9.3 Final Conclusion

Overall, this analysis identified the highest-ranked Cajun/Creole, Seafood, and Southern restaurants in New Orleans after adjusting for differences in reviewers' rating habits. **3 Southern Girls** ranked highest using reviewer-normalized scores, while census tract **22071003702** had the highest average normalized restaurant score among eligible geographic areas.

The findings demonstrate how reviewer behavior and geographic boundaries can influence restaurant comparisons. Although normalization provides an alternative perspective to traditional ratings, the results should be interpreted alongside review counts, sample sizes, and geographic limitations rather than treated as definitive measures of restaurant quality.

## 10. Data Management & Reproducibility

### 10.1 Handling Large Yelp Datasets

The Yelp Open Dataset contains large JSON files that require careful data management. The original business and review datasets were obtained from the Yelp Open Dataset and stored locally in data/raw/. After downloading the Yelp Open Dataset, the archive was extracted locally to access the business and review JSON files used for data preparation. These files were not uploaded to GitHub because of their size.

The business dataset was imported using `jsonlite::stream_in()`, while the larger review dataset was processed in smaller chunks to reduce memory usage. The data was then filtered to New Orleans restaurants and their associated reviews, reducing the amount of data needed for the remaining analysis.

After cleaning, the datasets contained 2,259 restaurants and 476,421 reviews. These were saved as compressed RDS files to avoid repeatedly importing and processing the original JSON files.

The combined review dataset exceeded GitHub's 100 MB file size limit, so it was divided into two smaller files: `reviews_part1.rds` and `reviews_part2.rds`. These files were combined using `bind_rows()` during the analysis.

This approach reduced repeated processing, made the project easier to manage, and allowed the cleaned data and analysis code to be maintained separately from the original large JSON files.
